# Product Discovery

A Globaly product-discovery pass. Goal: turn a fuzzy idea into a sharp, testable problem
before anyone writes a PRD or code.

## When to use
- A new feature or product idea arrives without a clear problem.
- Someone asks "is this worth building?" or "who is this for?"
- Before `/to-prd` or any planning skill.

## Process

1. **Restate the problem** in one sentence: *"<user> struggles to <job> because <obstacle>."*
   If you can't, you don't understand it yet — ask.
2. **Name the target user** precisely. "Everyone" is not a user. Pick the narrowest wedge.
3. **Jobs-to-be-done**: what is the user hiring this for? List the functional + emotional job.
4. **Current alternative**: what do they do today (a competitor, a spreadsheet, nothing)?
   The status quo is the real competition.
5. **Riskiest assumptions**: list the 3 beliefs that, if wrong, sink the idea. Rank by
   (impact × uncertainty).
6. **Smallest viable test**: for the #1 risk, design the cheapest experiment that could
   falsify it (interview, fake-door, prototype, concierge).

## Output
Write a short discovery brief with the six sections above. End with a clear
**Go / Pivot / Park** recommendation and the one test to run next.

## Globaly notes
- Bias to the narrowest wedge that creates a 10x-better experience for one user.
- A discovery brief is cheap; a wrong PRD is expensive. Spend the time here.
