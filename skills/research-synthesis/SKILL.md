# Research & Development — Synthesis

Turn a pile of raw inputs into a small set of well-evidenced, actionable findings.

## When to use
- After user interviews, surveys, competitor scans, or ticket reviews.
- When someone asks "what are the patterns?" or "what should we do about this?"

## Process

1. **Tag, don't summarize (yet).** Read every input and tag each observation with a short
   label. Keep observations atomic — one fact per tag.
2. **Cluster into themes.** Group related tags. A theme needs ≥3 independent observations
   from ≥2 sources to count — otherwise it's a hunch, label it as such.
3. **Score each theme**:
   - *Evidence strength* (how many independent sources)
   - *Confidence* (high / medium / low)
   - *Impact* (on the decision at hand)
4. **Separate signal from noise.** Quote the strongest 1-2 verbatim pieces of evidence per
   theme. Flag anything that contradicts the theme — disconfirming evidence is gold.
5. **Recommend.** For each high-impact, high-confidence theme, state the action it implies.

## Output
A findings doc: ranked themes, each with evidence count, confidence, 1-2 supporting quotes,
contradicting evidence (if any), and a recommended action. Lead with the single most
decision-relevant finding.

## Globaly notes
- Never launder a single anecdote into a "theme." Confidence labels protect future decisions.
- Cite sources so findings stay auditable when revisited.
